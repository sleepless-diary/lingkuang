# 演变 —— 实体的版本历史（方案 + 实现记要）

> 用户 2026-09-12 定方向、2026-09-13 细化并落地第一版。
> 原话：「我想给每个世界搞个git」「时间线本身就可以充当git啊，事件节点就是不同的版本」
> 「每个实例版本随事件节点变化，内容就是实例版本随事件节点变化」「每个git保存与上一节点的区别」
> 「我想在设定库右侧加一条竖着的等距的时间线，用来储存不同节点，当选中实例时，默认进入离当前指针最近的 git」
> 「都做吧，把模式放到设置里面」（三种记录模式）。

## 一句话

**一条设定（实体）= 一份初稿 + 一串"在某个事件之后变成这样"的差异**。
时间线上的事件节点就是版本锚点；设定库右侧那条竖线就是版本表；点哪一格就看哪一版。

## 例子

> 银发少女 —— 初稿：17 岁、银白发
> 　「第一次魔潮」那一帧：年龄 → 19、正文加一行
> 　「霜冠加冕」那一帧：能力 → 霜、冰晶
>
> 站在「霜冠加冕」那一格看到的是三者的叠加；站在「初稿」看到的是 17 岁的她。

## 右侧那条竖线（帧条）长什么样

像 `git log`：**每格等高**（46px，不按时间比例），顶上第一格永远是「初稿」，
往下**只列已经留过版本的事件**（2026-09-13 上午按用户要求改：
「我希望没有版本的节点就不显示」—— 原先把世界里每个事件都画一格，7 个节点里 6 个是空的，
看着像待办清单而不是历史）。有版本的格子带一个点、显示差异摘要（如「年龄、瞳色、正文」）。

底部三个东西：

```
记到 [327 第一次魔潮 ▾]      ← 新版本记在哪个事件上（默认 = 离沙盘指针最近的那个事件）
＋ 记一帧                     ← 在「记到」那个事件上留一版（正站在某版本上时，右边还多一个「删掉这一帧」）
（一行小字）手动模式：现在改的是初稿；要给某个事件留版本，用下面的 ＋
```

⚠️ 帧条上**点不到"没有版本的事件"**了（它们不显示）⇒ 想给它们留版本，就用底部的「记到」下拉选中它。

## 存储：还是那一个 `.md`（Obsidian 里能看到）

实体文件 `vault/<世界>/_设定/<类型>/<名字>.md`：

```
---
id: e-evo-a
name: 银发少女
type: 角色
年龄: 17          ← frontmatter 这几行 = 初稿（第 0 版）
发色: 银白
---

#正文：
（初稿的正文）

#演变：
每帧只记与上一帧的区别（叠加在上面 frontmatter 的初稿上）；锚点是时间线上的事件节点。

```json
[
  { "nodeId": "n-evo-2", "world": "测试世界观", "tlId": "tl-主线", "note": "第一次魔潮", "at": 1789…,
    "patch": { "set": { "年龄": "19" },
               "doc": { "hunks": [ { "at": 0, "del": [], "ins": ["【补写】"] } ] } } },
  { "nodeId": "n-evo-3", "…": "…", "patch": { "set": { "能力": "霜、冰晶" } } }
]
```
```

几条设计取舍（都是"数据安全优先"）：

- **为什么用 ```json 围栏**：Obsidian 的属性面板只认扁平键值，嵌套数组塞 frontmatter
  既不好读、也不好写回；围栏里的 JSON 能**原样往返**（实测 200 帧逐字节一致）。
- **为什么"只记区别"**：没动的字段不重复存。200 帧 + 120 行正文的文件 88 KB；
  要是每帧存全量，同一份数据要几百 KB 起。
- **正文按行存**（`hunks`：`at` = 上一版里的行号，从大到小排、从后往前应用，不用算偏移）。
  改得比正文还长、或改得太大（LCS 表超上限）时自动退回 `full`（整段存）。
- **解析不了就原样留着**：`#演变：` 段在、但 JSON 读不出来（在 Obsidian 里手改坏了）时，
  主进程打 `_framesBroken` 标记并把**原文**带回去，下次写盘照抄那段 —— 宁可界面暂时没有历史，
  也不能把历史写没。
- **锚点节点被删了，帧不删**：只在右栏显示成一格「孤立 · 节点已删除」。

## 三种记录模式（设置 → 设定演变；默认手动）

| 模式 | 什么时候产生"一版" | 改动落到哪一版 |
| --- | --- | --- |
| **手动**（默认） | 只有点「＋ 记一帧」才会留一版 | **你现在看的那一版**（初稿 or 帧条上选中的那一帧）—— 所见即所改 |
| **自动** | 改动直接落到底部「记到」那个事件上；它还没有版本就自动开一版 | 那个事件（视图跟着站过去） |
| **锁定** | 不新开版本 | 永远是设置里锁定的那一帧（帧条与视图都钉在它上面） |

三种模式都不弹窗：**落点写在右栏底部那行小字上**（如"手动模式：改动改的就是这一版（第 2 版）"、
"自动模式：改动会记到「霜冠加冕」上（还没版本就先建一版）"）。

⚠️ 2026-09-13 上午的语义变化：帧条不再显示"没有版本的事件"之后，"站在空格子上改 = 改到上一版"
这条中间态从界面上消失了（那种格子点不到）。所以「手动」现在只有两种明确情形：站在初稿 = 改初稿，
站在某一帧 = 改那一帧。想"从这一刻起才算一版"，先在下拉里选好事件再点「＋ 记一帧」。

## 为什么不会卡（用户提的"注意优化"）

拖帧条时每换一格都要显示那一版的样子。如果每换一格就从初稿重算，n 帧要算 n(n+1)/2 次（O(n²)）。
现在的做法：`statesOf(实体)` **一次算出全部前缀**（初稿 → 第 1 帧后 → 第 2 帧后 …），
换版本就是换个下标取数组（O(1)）；store 一有变化就把这份缓存作废，下次访问重算一遍。

实测（200 帧 + 120 行正文，`tools/e2e` 之外的一次性探针，数字留档在 `docs/BUGS.md` 第二十一轮）：

| 动作 | 耗时 |
| --- | --- |
| 打开设定库 → 帧条出现（201 格） | 107 ms |
| 换一版（缓存热，含 tiptap 换文档） | 平均 47 ms（27–55 ms） |
| 换一版（缓存刚作废，要重放 200 帧） | 平均 31 ms（27–39 ms） |
| 改一个字段（算差异 → 写 store） | 28 ms |
| 改一段正文（算行级差异 → 写 store） | 12 ms |

结论：**瓶颈不在物化**（重放 200 帧与缓存热基本同量级），而在显示那一版正文时 tiptap 换文档。
真要再快，下一步该动的是"换文档只 diff 不重建"，不是缓存策略。

## 语义边界（现在不做，写清楚免得误会）

- **重命名/换类型**：文件名与目录始终按**初稿**的名字与类型（`.md` 要有个稳定落点）；
  在某一帧上改名只影响那一版**显示的名字**。
- **回收站**：帧跟着实体文件走（同一个 `.md`），删实体进回收站时历史一起进去。
- **不碰循环/剧情线**：这一版只锚在事件节点上。
- **孤立帧**（锚点节点被删）会显示但不再参与排序语义。
- 手动模式在"没有版本的格子"上编辑时，改的是**上一版**（往回看也会变）——
  右栏会写明是哪一版，想让它从这一刻起才算，先点「＋ 在这一格记一帧」再改。
