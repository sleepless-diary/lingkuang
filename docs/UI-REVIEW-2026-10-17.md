# 界面评审与整改（2026-10-17）

> 触发：用户问「你觉得这个应用界面有没有可以优化的地方」→ 用真实数据截图量测后给出 12 项
> → 用户回「全做了吧」⇒ 本文记录**每一条的问题（实测数字）、改法、改完的实测值**，以及
> 剩下的技术债。截图前后对照在 `.review/shots/`（改前）与 `.review/shots-after/`（改后），
> 都是**真实数据**跑出来的（不是空库）：世界「维斯莱特」、5 条时间线、112 个实体、25 个节点。

## 0. 评审方法（为什么不是"读代码猜"）

复制 `%APPDATA%\lingkuang\worldbuilding.json` + `F:\lingkuang-vault` 到 `.review/run/`，
用测试后门起**隔离实例**（`LINGKUANG_TEST_DATA / VAULT / TEST_USERDATA / WINDOW_POS / SIZE / NOFOCUS`），
CDP（`--remote-debugging-port`）逐个工具截图 + 取 DOM 实测值（字号、宽度、对比度、CSS 变量是否解析）。
工具脚本：`.review/ui-shots.cjs`（巡览截图）、`.review/measure-after.cjs`（版式/字号/页签）、
`.review/verify.cjs`（token 解析 + 对比度 + 窄窗截图）、`.review/check-detail.cjs`（节点详情面板）。

窗口 1500×950（`innerWidth` 1488、dpr 1.5），窄窗用 `Emulation.setDeviceMetricsOverride` 模拟 960。

## 2. 明确**没有**动的设计决定

- **标尺文字的距离淡出**（`src/ui/timeline.ts` 每帧写行内 opacity，正态分布、无 transition）——
  用户 2026-09-26 明确要的就是这个。**只把字号 9→11px，没碰不透明度逻辑**。
- **AE 风小圆角**（`--radius:2px`）：`style.css` 覆盖设计系统给网页产物的 8px，保留。
- **灵感触发器全宽**（inspire）—— 它是横向多列的画布，不该收进 1200。
- **时间线「非线性」按钮 / 剧情线下拉 / ＋节点/＋剧情线/＋循环**的布局：只抬了字号与高度，没重排。

## 4. 剩下的技术债（下一轮再动）

1. `style.cssText` 仍有 **92 处**、TS 里 `style="..."` **492 处**、硬编码 `font-size:Npx` **95 处**。
   原语已经就位，剩下的是逐模块替换（settings / schema / props-panel / fields / detail 是重灾区）。
2. `style.css` 里还有 **42 个** `font-size:Npx` 字面量（多为 2–4px 的装饰点、或与 `--text-*` 同值）。
3. **密集时间线的节点名会互相压住**（12px 之后更明显）：真实数据里 5 个相邻节点字号一抬就叠字。
   正确解法是标签碰撞避让 / 阶梯换行（像 AE 的 label 排布），属于时间线的独立需求。
4. 窄窗隐藏 `#cx-rail` 是**取舍**：窄到 1100 以下时看不到「演变」。若需要，可给帧条做可折叠抽屉。
5. 助手面板（380px 停靠）里的小字仍是 11–12px 的密集排版，值得单独review一轮信息层级。
