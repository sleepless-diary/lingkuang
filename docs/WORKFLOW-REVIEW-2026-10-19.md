# 2026-10-19 工作流评审：四项改造

> 起点问题（用户）：「你觉得我这套世界观管理工作台有没有可以优化的地方，**比如功能可视性和工作流**」。
> 上一轮（`docs/UI-REVIEW-2026-10-17.md`）评的是**视觉与版式**，这一轮评的是**流程走不走得通**。
>
> 结论一句话：**功能不缺，缺的是最后一米的路和全局导航。**
>
> 用户当场答复：「**全做了吧**，但是联想**不是剔除已有设定**，是**选择部分设定变成实体**，除此之外**还可以自主添加词条**，
> 再加一个 **AI 总结**的功能，能把已选择的设定提炼成一个**完整角色**」；另：「**ctrl+k 一只手有点难按，能不能换一个快捷键**」。

## 1 数据证据（真实库，不是推测）

用隔离实例（`.review/run/` 的真实数据副本，端口 9361）实测：

| 事实 | 数字 | 说明 |
|---|---|---|
| 实体 | 112 条 | 规模已经不小 |
| 正文（≥20 字）的实体 | **6** 条 | 106 条基本只有字段 |
| 有演变帧（`frames`）的实体 | **0** 条 | 右栏帧条、「这件事改变了谁」永远是空的 |
| 时间线节点 | 25 条（21 有描述、**0** 有正文） | 事件都停在一句话 |
| `properties` 键频次 | 所属 112 / 描述 110 / 类型 107 / 能力 83 / 别名 82；性别·种族·年龄·发色·瞳色·身高·外貌 各 **65** | 约 65 条是抽卡生成的模板卡，另 ~47 条手写 |
| 时间线 | 5 条（1 条 25 节点、3 条 0 节点、1 条同名） | 结构能力过剩，实际只用 1 条 |

`docs/DESIGN.md` §5 的架构前提是「**内容本体 = Markdown 文稿**，面板是派生视图」。
但数据说明创作者实际在用「**卡片字段**」工作：稿件与演变的使用率是 6/112 与 0/112。

## 2 四项改造

### A 创作闭环（抽卡 / 联想 → 实体 → 事件）

- **新增 `src/ui/intake.ts`**：「选中词条」工作栏，挂在联想画布工具条下方。
  - 词条可**逐条删**（`×`）、可**自己补**（输入框回车）——选择权在人，不做任何自动过滤。
  - 「**建为设定**」：原样落成一条实体（正文给 Markdown 骨架，不再是空稿）。
  - 「**AI 提炼成角色**」：把这一把词交给当前 AI 供应商，收成 `{名字 / 一句话 / 分段字段 / 正文}`，
    先出**预览**（字段 chips + 正文前 900 字），点「采用，建为设定」才落盘；解析失败时整段当正文、不丢模型输出。
    Prompt 在 `DISTILL_SYS`，解析器 `parseDistilled()` 容忍 ```json 围栏、前后散文、尾逗号。
- **`src/ui/inspire.ts`**：卡片头加两个出口 —— 「整组→暂存词」（送进上面的工作栏）与「整组存为设定」
  （`createEntityFromCard()`：词条名直接当字段名，正文按分组给 `## 外观 / ## 背景 …`）。
- **`src/ui/codex.ts`**：实体面板新增「**它出现在哪些事件**」（`#cx-events`）——
  与节点侧的「这件事改变了谁」互为镜像，读 `Entity.frames[].nodeId`，按时间排，点一行跳到那个事件。
  空态给出去处（去右栏帧条记一帧 / 去事件侧反向改），而不是一片空白。
  ⚠️ **没有**加「一键建事件」：帧必须携带真实差异（`PatchFrame`），空帧没有语义 —— 加个按钮只会造垃圾数据。

### B 空稿可见

- `src/ui/codex.ts`：正文不足 20 字的实体在树行尾挂 **「草稿」** 药丸（与已有「待填」同一套视觉、
  不同色：待填=名字没起，草稿=名字有了正文没写）。
- 左栏搜索框右侧新增 **「待补稿 N」** chip：点开把全部世界的空正文实体摊平成一张清单
  （复用搜索那一支的扁平渲染 + FLIP 动画）。真实库实测 `待补稿 106`、行数 106、树行标签 106 个。

### C 全局检索与快捷键

- **新增 `src/ui/palette.ts`**：命令面板（`Ctrl+P`），覆盖设定条目（名字/别名/类型/世界）、
  时间线节点（标题/描述/种类/时间线）、工具、世界集，共 149 条（112 + 25 + 11 + 1）。
  键盘 `↑↓` 选、`Enter` 去、`Esc` 关；点空白也关。
  跳「设定条目」= 写会话目标（`rememberTarget`）+ 点左栏 `[data-tool="codex"]` —— 复用整条「切工具」的路，
  不另写一份 `openTool`。
- **助手热键改成 `Ctrl+J`**（`Ctrl+K` 保作别名）：`src/ui/shell.ts` 的 keydown 里 `key === 'j' || 'k'`。
- 没做的：vault 里**不属于任何条目**的散篇 `.md`、地图、词库暂不进面板 —— 它们要么没有 id 体系、
  要么得走主进程列目录，留给下一轮。

### D 数据治理

- **素材库不再是占位**：`src/ui/library.ts` 词库浏览器（61 分类、4669 词条）。
  分类列表带计数、跨分类关键词搜索、点 `＋` 把词放进「选中词条」（直通 A 的闭环）。
  ⚠️ 加载走 **`lingkuangAPI.loadCharLib()` 优先、`fetch` 兜底** —— 生产构建 `app-dist/` 里**没有** `data/`
  目录（vite 只打 src），只写 fetch 的话打包后这页永远是「词库没加载出来」。
- **类别整理**（`src/ui/type-migrate.ts` + 结构体管理页的「整理类型…」按钮）：
  把字段「类型」的值提升成真正的 `typeId`。真实库实测：会搬 **85** 条、新建 **13** 个类型、复用 1 个，
  17 条已在正确类型下，另有 10 个单条类别**先不动**（避免冒出几十个只有一条的类型）。
  四条纪律：
  1. **类型 id 直接用类别名**（老数据就是 `id = 名字` 的写法）。造 `et_1` 这种机器 id 会让 vault 目录、
     frontmatter `type`、重扫时的 `typeId` 三处对不上 —— 实测「类型行都在、85 条实体全归不进去」。
  2. 多值写法先归一化（`物品/科技/魔法` → `物品`，`primaryCategory()`）：类型名要进 vault 目录名，斜杠会造嵌套目录。
  3. 执行顺序：**先 `backup:create('data')`**（失败就整件事不开始）→ 改 `typeId` → 逐条
     `vault:delete-entity`（按 id 把旧目录那份移进回收站）→ `vault:write-entity`（写新目录）。
     顺序不能反，反了会把刚写的新文件当成旧的删掉。
  4. `properties['类型']` **一律保留**（不删只标）。
- **素材库第二页签「vault 文件」**（同 `src/ui/library.ts`）：素材库本来是「上游词库」的只读浏览器，
  但真实写作时人真正要找的是**自己 vault 里那 137 个 `.md`**。这页签把 vault 变成可浏览的：
  1. **列目录**：`lingkuangAPI.fs.list(dir)`，只列**文件夹 + `.md/.markdown/.txt/.json`**（`.obsidian/.trash` 这类不进列表）；
     面包屑取 `r.root.label` + 相对路径（`【灵框库（vault）】维斯莱特/_设定`），计数写「N 个文件 · M 个文件夹」。
  2. **进子目录 / 上一级**：`#lib-up` 到根就停住，不会跳出 vault。
  3. **全库内容搜索**：`lingkuangAPI.fs.search(vaultRoot, q)` 一次扫全库，命中行显示 `文件:行号` + 该行原文；
     实测真实副本「设定」→ `36 处命中 · 扫了 137 个文件`。
  4. **预览**：点命中行读 `fs.read(file)`，从命中行起显示 **≤220 行**，头上有文件名、完整路径、`850 B · 19 行 · 命中第 3 行`、
     「复制路径」；点普通文件则从头显示。
  - 这页**只读、不写盘**（要编条目请去设定库 / Obsidian）—— 与「素材库不做编辑」的口径一致。
- **时间线重名拦截**：`＋` 改成先问名字（默认 `新时间线 2/3…`），同名不再 silently 堆第二条，
  而是直接切到已有那条（与 AI 侧 `create_timeline` 同名复用同一口径）。
- **空线收纳**：0 节点且**不是当前选中**的时间线折进一颗「空线 N」按钮（状态记 localStorage）。
  当前选中那条永远可见 —— 刚建出来的空线不会一建出来就消失。实测：5 条时间线 → 页签只剩 `主线 25` + `空线 4`。

### 顺带修掉两条真 bug

1. **`src/main.ts` 把 `typeId` 当类型名传给 vault**
   （`vaultWriteEntity(wsName, e.typeId, e)` 与 `flushSync` 的 `typeName: e.typeId`）。
   老数据里 `typeId` 恰好等于中文名（「角色」「地点」），所以一直没出事；
   一旦出现机器 id，vault 里就会长出一堆 `et_1/`、`et_2/` 文件夹，Obsidian 那边完全不可读。
   现在两处都取 `entityTypes[typeId].name` 兜底。
2. **`--danger` 与 `--muted` 的真实使用**：上一轮定下的口径（`--muted` 只做装饰、亮底强调文字用 `--accent-ink`）
   在新代码里继续沿用；本轮新增的样式没有引入新的颜色字面量，全部走 `design-system/tokens.css`。

## 4 刻意没做 / 留给下一轮

- **命令面板没覆盖 vault 散篇笔记、地图**（理由见 C）。vault 现在能在素材库里浏览/搜索了，
  但仍**没进命令面板的条目表**（`Ctrl+P` 跳的是实体/事件/工具/世界集）。
- **`Entity.frames` 仍无"一键"入口**：帧必须有真实差异，U I 上只能引导（见 A 的 ⚠️）。
- **类别整理的单条类别（10 个）先不动**：要治它们得先定「要不要给单条开类型」的产品口径。
- **素材库不做编辑**：词库是 CC BY-NC-SA 上游产物，编辑它牵扯许可证与合并，不在本轮范围。
- 技术债（上一轮记录的）仍在：`style.cssText` 92 处、内联 `style="…"` 492 处、
  TS 内联 `font-size:Npx` 95 处（本轮新代码用 `.lk-btn/.lk-chip/.lk-input/.lk-empty` 等原语，没再加）。
